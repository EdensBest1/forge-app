# Master Context

## 1. Master Rule

Codex must protect existing work first. Every future task should begin by reading the project rules, creating a checkpoint, inspecting the current files, and making only the requested additive change unless the user explicitly approves a broader edit.

This repository is a long-term knowledge system for organizing business strategy, app plans, legal work, SOPs, contracts, partner information, and future ChatGPT/Codex instructions. Codex only has access to files and text inside the repository or pasted into Codex. Do not claim external chats, exports, or documents have been imported unless those files are actually present.

## 2. Business Ecosystem

The ecosystem currently includes these major businesses, apps, and planning areas:

- Forge
- Stitch
- S&A Auto
- NorthStar Creative Co.
- Seneca Dev Co.
- Photography & Videography
- Legal/IP documents
- SOPs and contracts
- Future partner sections

Each section should grow over time through additive documentation, approved project plans, safe implementation notes, and clearly tracked decisions.

## 3. Forge Current Direction

Forge is a local services marketplace starting in Medford/Southern Oregon. It should allow customers to discover and request local providers and allow providers to apply to offer services. Provider-entered information remains unverified until documented human review.

Forge should protect trust, local reputation, service quality, customer intake, provider onboarding, payment readiness, and future operational workflows. Any future app work should reuse existing Forge components, routes, tables, and business logic where possible.

## 4. Photography & Videography Section

Customers can hire photographers and videographers for weddings, events, business content, social media content, real estate shoots, family photos, church/community events, music videos, and creative projects.

Dennis may be referenced only as an example local creative, not as the only provider, without an endorsement or verification claim. Do not include private contact information, private addresses, private messages, or sensitive personal details in this repository unless the user intentionally provides them in a secure private config.

## 5. S&A Auto

S&A Auto should have a placeholder section for auto sales, transport, trailers, diesel trucks, vehicle sourcing, dealer-license workflow through approved existing dealership relationships, and transaction documents.

Future S&A Auto planning should keep dealer-license workflow, vehicle sourcing, transport, customer intake, partner responsibilities, and transaction documentation clearly separated until the user approves specific implementation details.

## 6. Seneca Dev Co.

Seneca Dev Co. should have a placeholder section for construction, development, big projects, home projects, Washington, Oregon, and partner project intake.

Future Seneca Dev Co. planning should track construction/development project categories, geography, intake workflows, partner responsibilities, documents, approvals, and compliance requirements without exposing private partner details.

## 7. Legal Folder

The legal folder should organize trademarks, IP protection, contracts, SOPs, employment docs, partnership agreements, vendor agreements, investor docs, compliance docs, and transaction templates.

Legal documents should be treated as sensitive planning material. Do not present legal drafts as final legal advice, do not expose private information, and do not commit secrets or private credentials.

## 8. Codex Workflow

Every future Codex task must:

- Read `docs/master/CODEX_RULES.md` first.
- Create a checkpoint.
- Inspect existing files.
- Add only the requested feature.
- Reuse existing components.
- Avoid destructive migrations.
- Run tests if available.
- Update `docs/master/CHANGELOG.md`.
- Update `docs/master/FEATURE_REGISTRY.md` if a feature was added.
- Report files changed.
